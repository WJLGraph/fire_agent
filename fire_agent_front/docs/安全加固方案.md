### 0.2 v2 新增 6 项 v1 未发现的（其中 2 项是本项目最高危）

2. 🔴 **5 个业务端点完全没有鉴权**，匿名可读（2.2）
3. 🟠 `security.py:30-32` 在 **import 期**绑定 JWT 密钥与有效期，热改配置静默失效（2.3）

## 2. P0 · 可被直接利用（本周必修）

### 2.1 管理端点补授权：把 9 个 `get_current_user` 换成 `get_current_admin`

**问题**：`app/api/v1/routes/admin.py` 里只有 `:729 /users`、`:752 /users/{id}/role`、`:773 /users/{id}` 三个端点用了 `get_current_admin`，其余 9 个挂在全局 `/admin` 前缀下的端点只依赖 `get_current_user`：

| 行号 | 端点 | 普通用户能做什么 |
|---|---|---|
| `:197` | `GET /admin/config` | 读回全部厂商配置（脱敏值仅露尾 3 位） |
| `:203` | `POST /admin/config` | **改写 LLM / AMD / LongCat / 高德 Key 并落盘 `.env`** |
| `:265` | `POST /admin/test/db` | 用任意连接串探测内网数据库 |
| `:279` | `POST /admin/test/llm` | 以任意 Key 发起外部请求（SSRF + 白刷额度） |
| `:311` | `GET /admin/llm/models` | 枚举模型清单 |
| `:540` | `GET /admin/bailian/quota` | 读配额与账户信息 |
| `:553` | `GET /admin/model-status` | 读当前生效供应商与 Key 尾 3 位 |
| `:674` | `GET /admin/status` | 读运行时环境信息 |
| `:715` | `GET /admin/logs` | **读全站系统日志**（含他人查询原文与 prompt） |

这是本项目最高危项：不需要窃取凭据，只要注册一个账号即可纵向提权。攻击者把 `LLM_API_KEY` 换成自己的，全平台流量即经过其服务器；把 `DATABASE_URL` 换成自己的，可诱导后端写出数据。

**方案**（一次性，改动小）：

```python
# admin.py —— 全局收口，比逐端点改更可靠
from app.api.deps import get_current_admin

router = APIRouter(prefix="/admin", tags=["admin"],
                   dependencies=[Depends(get_current_admin)])   # ← 加这一行
```

> 用 **router 级 dependencies** 而不是逐个函数改：逐个改会漏，router 级默认全拦，将来新增端点自动继承。三个已经正确的端点无需改动，重复声明不影响行为。

**兜底（纵深防御，反代层）**：宝塔 Nginx 对 `/api/v1/admin/` 追加内网段白名单，见 §5。

**验收**：用普通用户 token 逐个 `curl` 上表 9 个端点，全部 403；`POST /admin/config` 后 `.env` 无变化。

### 2.2 补齐 5 个完全无鉴权的业务端点

**问题**：以下端点连 `Depends(get_current_user)` 都没有，只有 `Depends(get_db)`，公网匿名可直读：

- `dashboard.py:54`、`:81`、`:104` —— 大屏汇总数据（火情统计、资源分布）
- `query.py:39` —— 智能查询能力
- `agent.py:1168` —— **函数 docstring 自己写着"仅需登录态即可查看"，但代码里根本没有登录校验**，注释与实现矛盾

**方案**：

1. 逐个补 `Depends(get_current_user)`；若产品上确需匿名展示（大屏投屏），改为**独立的只读端点 + 专门的低权限 token**，而不是放开全站。
2. `agent.py:1168` 顺带修正 docstring 与实现的不一致——这类"注释撒谎"以后会变成"看起来有人验过了"的错觉。
3. 建立**清单化约束**：`scripts/` 加一个静态检查，遍历 `app/api/v1/routes/*.py` 的所有 `@router.(get|post|put|delete)`，凡路径不在 `auth/login|auth/register|health` 白名单内者，函数签名必须出现 `get_current_user` / `get_current_admin` / `optional_user` 之一，否则 CI 失败。

> 第 3 条是本节真正的价值所在。2.1 和 2.2 都是"漏了一个依赖"，人工审一次只能保证当下不漏；把鉴权变成可机器校验的不变量，才能持续不漏。

**验收**：`curl` 无 token 请求 5 个端点，全部 401。

> **落地时踩到的一条，值得记下来**：给端点加鉴权**必须和前端取数路径同批改**，否则会出现"接口 200 语义正确、页面却永远显示降级数据"的隐形回归。本项目就中过一次：`api/dashboard.js:15` 用的是裸 `fetch(url)`，从不带 `Authorization`；`/history-fires`、`/predict-risks` 一旦要求登录，前端每个调用都 401，而 `views/dashboard/index.vue:70` 一片 `.catch(() => null)` 把 401 静默吞掉 → 状态标签恒为"本地降级数据"，日志里却是干净的 401。已修：该模块统一走 `authFetch`（顺带享受 §3.8 的 `X-Token-Refresh` 静默续期），实测同一 token 下 `/history-fires` 返回 5411 条、`/predict-risks` 返回 11680 条。**排查口诀**：页面显示"本地降级"但后端日志有 401，先怀疑前端没带头，而不是数据源坏了。
>
> 更根本的一条（列入 4.5 的门禁候选）：`catch(() => null)` 这类"把任何异常都翻译成降级"的写法会吃掉鉴权错误。降级只应在**网络失败**时发生；401 应交给 `authFetch` 跳登录，403/5xx 至少要把 message 显示出来。

### 2.3 JWT 密钥：禁默认值 + 修 import 期绑定

两个独立缺陷，要一起修，否则会出现"密钥配对了但没生效"的诡异现象。

**① 默认值**（`config.py:27`）：

```python
JWT_SECRET: str = ""          # 去掉硬编码默认
ACCESS_TOKEN_EXPIRE_MINUTES: int = 120
```

`main.py` lifespan 内校验：

```python
if not settings.JWT_SECRET or settings.JWT_SECRET.startswith("fire****"):
    if os.getenv("ENV") == "production":
        raise RuntimeError("生产环境必须配置强随机 JWT_SECRET")
    logger.warning("JWT_SECRET 使用开发默认值，禁止用于生产")
```

生成方式：`python -c "import secrets; print(secrets.token_urlsafe(64))"`，长度 ≥ 48 字节，不进 git（`.env` 已在 `.gitignore`，需在 README 部署章节再次强调）。

**② import 期绑定**（`security.py:30-32`）：

```python
SECRET_KEY = settings.JWT_SECRET          # ← 模块导入时就固化了
ALGORITHM = settings.ALGORITHM
ACCESS_TOKEN_EXPIRE_MINUTES = settings.ACCESS_TOKEN_EXPIRE_MINUTES
```

后果：`.env` 改动或经 `POST /admin/config` 热更新后，**已加载的 security 模块仍用旧值**，表现为"配置页显示新值、签发仍是旧密钥"。改为调用点读取：

```python
def create_access_token(...):
    secret = settings.JWT_SECRET                       # 运行时取
    expire = settings.ACCESS_TOKEN_EXPIRE_MINUTES
def decode_token(token):
    jwt.decode(token, settings.JWT_SECRET, algorithms=[settings.ALGORITHM])
```

> 顺带一个**必须一起定的策略**：`JWT_SECRET` 一换，所有存量 token 立即失效，用户被集体踢下线。宝塔上换密钥前先选好时间窗口。

**验收**：临时移走 `.env` 里 `JWT_SECRET`，`ENV=production uvicorn ...` 应启动失败；改密钥后旧 token 立刻 401（证明运行时读取生效）。

> 1. 校验放在 **import 期**而不是 lifespan——lifespan 要等 ASGI 起来才跑，`--reload`/worker 预热阶段的报错更难定位；import 期拒绝让进程连端口都不占。

### 3.5 NULL 属主的 IDOR（修正 v1 §3.4 的"已做鉴权"）

```python

```

任何 `user_id` 为空的历史文档（早期数据、系统导入、导入脚本产物）对**全部登录用户**可读全文（`:326`）并可下载原件（`:344`）；而删除在 `:357` 用严格 `!= user_id`，于是形成"人人能看、只有主人能删"的不对称。

**方案**：读写与删除统一为同一判据，并明确 NULL 的语义：

```python
def _assert_doc_access(doc, user_id, is_admin):
```

### 3.7 CORS 收敛

`main.py:112-118` 为 `methods=["*"]` / `headers=["*"]` / `credentials=True`。生产同域反代时浏览器根本不发跨域请求，因此：

```python
if not _is_prod:
    app.add_middleware(CORSMiddleware, allow_origins=settings.CORS_ORIGINS, ...)
```

`config.py:32` 的 CORS 默认值仅开发用；生产若仍需跨域，白名单精确到域名，`allow_methods` 只列四种、`allow_headers` 只列 `Authorization, Content-Type`。

> **落地与本节草案的差异（有意为之）**：中间件**没有**用 `if not _is_prod` 包住，而是无条件挂载——生产同域反代时浏览器压根不发跨域请求，挂与不挂对公网攻击面没有区别；反而一旦哪天需要跨域调试，不必改代码。真正收紧的是三个参数本身（`main.py:187-196`）：`allow_methods` 收成 `GET/POST/PUT/DELETE`、`allow_headers` 收成 `Authorization/Content-Type`、并新增 `expose_headers=["X-Token-Refresh"]`。最后这条是 15h 滑动续期的硬依赖：不 expose 的话跨域下前端读不到续期头，用户会"每 15 小时被踢一次"而不是滑动续期。生产仍建议把 `CORS_ORIGINS` 精确写到自己域名（§7.5）。

### 3.8 Token 生命周期

- `config.py:29` 有效期 24h → 常规 2h，大屏场景 4h。
- **吊销用 `token_version`，零外部依赖**：`users` 表加整数列，签发时写入 payload，鉴权时对比；改密（`auth.py:92-102` 目前完全不动它）与登出时 +1，旧 token 立即失效。比 Redis jti 黑名单省事得多，且当前项目没有 Redis。
- 无感刷新：响应头 `X-Token-Refresh`，`api/http.js` 静默换新。
- localStorage 前提不变，因此 3.6 与 CSP 的优先级被拉高；长期可评估 httpOnly Cookie + SameSite=Lax（需配套 CSRF token）。

> **落地口径（按你的硬性要求改成 15 小时滑动，不是草案里的 2h/4h）**：`ACCESS_TOKEN_EXPIRE_MINUTES = 15 * 60`，会话存续期间任意一次带凭证的请求都会在 `X-Token-Refresh` 里拿到一枚同 payload 的新 token（exp 再往后推 15h），前端静默替换 localStorage。于是语义正好是你要的两句：**15 小时内出现过登录动作 → 从那次动作重新计时；连续 15 小时一次请求都没有 → 最后一枚 token 到期 → 401 → 回登录页**。三个实现细节值得记：
> 1. 中间件写成**纯 ASGI**（`app/core/session.py:29`）而不是 `BaseHTTPMiddleware`——后者会给每个响应加一层缓冲包装，对本项目大量使用的 `StreamingResponse` / SSE 长连接是已知风险点；这里只在 `http.response.start` 消息上补一个头，不碰消息体。
> 2. 前端只在**真实活动**（pointerdown / keydown / wheel / visibilitychange，10 分钟窗口内）之后才吸收续期 token，否则一个一直轮询的后台标签页会把自己续成永生，15h 规则形同虚设。
> 3. 存量老 token 的 payload 里没有 `tv`，实现按 `tv=0` 处理、与 `users.token_version` 的列默认值相等 → **上线这次改动不会把任何人踢下线**（草案里"改密钥/加版本必然集体掉线"的顾虑只属于换 `JWT_SECRET` 那一刻，见 §7.5）。
> 登出：`stores/auth.js` 的 `logoutRemote()` 先 `POST /auth/logout`（失败也照样清本地，不因后端不可达而困住用户）；改密走 `token_version + 1`，旧 token 立刻 401。

### 3.9 日志脱敏

## 4. P2 · 加固与门禁

### 4.1 HTTPS、安全响应头与 CSP

全站 HTTPS + `Strict-Transport-Security: max-age=31536000; includeSubDomains`。安全头统一在 Nginx 加（§5），应用层不重复。**CSP 上线前先用 `Content-Security-Policy-Report-Only` 观察一周**——本项目有三类易误伤资源：天地图/高德瓦片、Web Worker（`worker-src 'self' blob:`）、以及 `index.html` 的 CDN 脚本；不加 report-only 会直接白屏。

### 4.2 限流矩阵

| 端点 | 阈值 | 位置 |
|---|---|---|
| `/auth/login`、`/auth/register` | 5 次/分/IP | Nginx |
| `/query/execute`、`/agent/tasks`、`/rag/ask`（LLM 计费） | 10 次/分/用户 | 应用层（slowapi） |

```nginx

    server_name your-domain.cn;
    server_tokens off;                    # 新增：错误页不泄露框架
    client_max_body_size 25m;             # 新增：外层体积兜底（配合 3.4）
```

1. **改完用 `nginx -s reload` 而不是重启站点**——重启会硬切所有 SSE 长连接，Agent 中心正在跑的任务会掉线。
2. **`/api/v1/admin/` 白名单**：宝塔自己的面板走 `/www/server/panel`，与本规则无冲突，但若你从公网 IP 管理后台，这条会把你自己的管理页锁在外面——先确认出口 IP 再加。
3. **`access_log off` 只对 `/api/v1/agent/` 关**，别整站关，否则 4.7 的 401/403 告警失去数据源。
4. **`base:'./'` + `createWebHistory`**：`vite.config.js` 目前 `base:'./'`，深链到 `/welcome/features` 这类两段路径时相对资源解析会错位（已实测能命中 `200 text/html` 的坑）。宝塔站点若部署在**子目录**，这个组合迟早出问题；部署在域名根则影响可控。是否改成 `base:'/'` 取决于你的站点布局，见文末待确认项。

### 7.5 上线开关：三个 ENV 键（本轮唯一还没拉开的闸）

2.x / 3.x 的代码改动已全部落地并通过验证，但它们大多**以 `ENV=production` 为前提**才生效。你现在的 `.env` 里根本没有 `ENV` 这一行，于是走的是 `config.py:28` 的默认值 `development`——**宝塔上跑的就是这个默认值**。下面三个键是"代码已就绪、等你打开"的部分。

| 键 | 当前状态（本机 `.env` 实测） | 生产应设为 | 不打开的后果 |
|---|---|---|---|
| `ENV` | **缺失** → 取默认 `development` | `production` | `/docs`、`/redoc`、`/openapi.json` 全部公网可达（2.4 白做）；JWT 弱密钥只告警不拒绝启动（2.3 白做） |
| `JWT_SECRET` | 已配，但**值就是 `.env.example` 里那把公开过的模板占位值**（45 字节，长度达标；此处不重抄明文，它已在后端仓库历史里，`git show 0518af0:.env.example` 可见） | `python -c "import secrets;print(secrets.token_urlsafe(64))"` 的输出 | 任何读过 `.env.example` 或 git 历史的人都能自签一枚 `role=admin` 的有效 token——**这条比地图 Key 更严重**，因为它直接等于身份 |
| `ADMIN_INIT_PASSWORD` | **缺失** | 首次建库时设一个强口令 | 仅在"库里还没有 admin"那一次生效。你库里 admin 已存在 → 现在配不配都不影响运行；但换机/重建库时，生产环境会因缺它而拒绝启动（设计如此，为避免弱口令 admin 常驻） |

**关于 `JWT_SECRET` 本轮补的一道拦网**：原自检只判"空"和"长度 < 32"，而那把占位值长度 45、看着像配过了，`cp .env.example .env` 的人会被直接放过。现按公开值黑名单单独判定（`app/core/session.py:66-74`），并补了两个回归用例：`production` + 占位值 → 拒绝启动；`development` + 占位值 → 保留原值只告警（避免无谓地把本地已签发的 token 全打掉）。`.env.example` 里的密钥值同时改为留空，不再提供一个"能过校验的公开密钥"。

⚠️ **必须同批改、且有先后顺序**：先写 `JWT_SECRET`，再写 `ENV=production`。反过来会让服务当场起不来（`session.py:97` 抛 `RuntimeError`），而宝塔上"进程起不来"表现成 502，很容易被误判成代码问题。

改完后的**唯一用户可感知影响**：换签名密钥的瞬间，所有在手持 token 全部失效，每人重新登录一次。这一次无法避免，也正因为无法避免，建议放在低峰期做——这也是 §7 末尾"不建议同时动 S1 与 S3"的原因。
